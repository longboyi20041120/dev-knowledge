# PPT 生成 Agent

> 固定模板 + 可变内容。**3 题必答 + 智能推导 + 一键确认**，不让人填烦。
>
> **决策**：
> - V1：Claude Code Skill（对话问卷 → 大纲先审 → 逐章生成）
> - V2：独立 Web 应用
> - 模板：先做内置 3-5 套默认模板，用户模板拿到后再做解析
> - 生成策略：先大纲→确认→再逐章生成
> - 借鉴：GordenSun 的 edits.json 模式（不改排版只换字）、PPTAgent 的反思修复环

---

## 一、整体流程

```
用户: "帮我做一份PPT"
  │
  ▼
┌─────────────────────────────────┐
│ 第一轮：3 题快问（15 秒填完）      │
│ ① 主题 ② 时长 ③ 风格             │
│ → Agent 推导剩余 5 项             │
│ → 展示推导结果，用户一键确认/调整   │
└──────────────┬──────────────────┘
               ▼
┌─────────────────────────────────┐
│ 第二轮：AI 生成大纲               │
│ → 3-5 章节 + 每章页数估算          │
│ → 用户确认/调整                    │
└──────────────┬──────────────────┘
               ▼
┌─────────────────────────────────┐
│ 第三轮：逐章收集素材               │
│ → "第一章讲什么？有图/表吗？"      │
│ → 用户提供文字/图片/表格            │
└──────────────┬──────────────────┘
               ▼
┌─────────────────────────────────┐
│ 第四轮：逐章生成 + AI 自检         │
│ → 生成 → AI 自己检查格式/溢出      │
│ → 展示摘要 → 用户 ✓/✎             │
└──────────────┬──────────────────┘
               ▼
          输出 .pptx
```

## 二、问卷设计：3 题必答 + 智能推导

> 核心原则：**能推导的绝对不问，能从上下文猜的不让用户选。**

### 2.1 必答题（只问这 3 个）

```
Agent: 收到，做 PPT。先确认 3 件事——

       ① 主题是什么？
       ② 讲多久？ [5min] [10min] [15min] [20min] [30min]
       ③ 风格偏好？
          A. 简洁演讲型 — 大字少图，靠你讲
          B. 标准汇报型 — 图文并茂
          C. 详细阅读型 — 信息密度高
```

### 2.2 推导规则（用户不用管的 5 项）

| 推导项 | 规则 |
|--------|------|
| **听众类型** | 简洁→高管/客户；标准→同事/团队；详细→技术/学术 |
| **单页信息密度** | 简洁→低（1-3 要素）；标准→中（3-5 要素）；详细→高（5-8 要素） |
| **演讲者备注** | 默认不加，除非用户主动提 |
| **输出比例** | 默认 16:9 |
| **模板** | 默认用内置模板，用户有 .pptx 时切到用户模板 |

### 2.3 推导结果展示（一键确认）

```
Agent: 根据你选的，我自动推了以下配置——

       ┌────────────────────────────┐
       │ 主题：Q2 产品增长汇报        │
       │ 时长：15 分钟 → 目标 12-15 页 │
       │ 风格：标准汇报型             │
       │ 听众：同事/团队（自动推导）    │
       │ 密度：每页 3-5 要素（自动推导）│
       │ 比例：16:9                  │
       │ 备注：不加                   │
       └────────────────────────────┘

       没问题的话我开始做大纲？
       [确认，继续] [我要改某几项] [算了，我自己描述需求]
```

### 2.4 "我要改某几项"时展开

只有用户点"要改"时才展开完整问卷，平常不出现：

```
Agent: 哪项要改？
       [听众] [密度] [比例] [备注] [模板]
```

### 2.5 "我自己描述需求"时

如果用户就是不想填问卷，允许一句话搞定：

```
用户: 帮我做 Q2 汇报，15 分钟，给同事看，重点讲数据增长

Agent: 收到，推导如下——[展示推导结果]
       确认吗？
```

## 三、内容收集：逐章收，不全问

### 3.1 支持的素材

| 类型 | 格式 |
|------|------|
| 文字内容 | 自然语言 / Markdown |
| 图片 | .png / .jpg 路径 |
| 表格 | Markdown 表格 / CSV / 自然语言描述 |

### 3.2 逐章收集（一章一章来）

```
Agent: 大纲 4 章 14 页，开始第一章——

       ▸ 第一章：Q2 核心指标（3 页）
         这章包含什么？
         · 有什么关键数字？
         · 有图吗？（路径或拖进来）
         · 需要对比上季度吗？

用户: DAU 120→180 万 +50%，收入 800→1200 万
      图在 C:\Users\xxx\Desktop\chart.png
      不需要对比

Agent: ┌─ 第一章生成结果 ─────────────────┐
       │ 第1页：Q2 核心指标概览            │
       │       3 个 KPI 数字 + 变化箭头    │
       │ 第2页：DAU 增长趋势               │
       │       标题 + chart.png + 一句话   │
       │ 第3页：收入分析                   │
       │       标题 + Q1/Q2 对比表格       │
       └────────────────────────────────┘

       [✓ 通过，下一章] [✎ 改某页] [⏸ 暂停]
```

## 四、借鉴：GordenSun 的 edits.json 模式

### 4.1 核心理念：不改排版，只换文字

```
传统的做法（我们之前的思路）：
  python-pptx 从零画 → 每页写代码控制位置/颜色/字体

GordenSun 的做法（应该学）：
  模板.pptx             ← 排版/配色/字体全部固定
  edits.json            ← 只写"第1页标题填什么""第3页正文填什么"
  build_pptx.py 合并    ← 不改模板原文件，输出新文件
```

### 4.2 好处

- 用户模板的排版 100% 保留
- edits.json 可版本控制、可 diff、可复用
- 同样的内容换不同模板只需要换模板路径
- AI 不需要理解排版，只需要理解"这个槽位放什么内容"

### 4.3 编辑铁律

1. **不改排版** — 位置、大小、颜色、字体、字号、行距，一律不动
2. **所有占位符必须替换** — 模板里任何"请输入标题"之类的占位文字必须换成真实内容
3. **禁止省略号截断** — 文字太长时重写精简，不许加 `...`
4. **同级标题字号一致** — 不能因为某处字多就把它改小

## 五、借鉴：PPTAgent 的反思修复环

### 5.1 怎么做

```
逐章生成后，Agent 自己扫一遍：

检查项：
├── 有没有占位文字没替换？
├── 有没有文字超出文本框？（需 python-pptx 检测）
├── 同级标题字号是否一致？
├── 相邻页风格是否统一？
├── 图片路径是否有效？
└── 有问题 → 自己修 → 再扫一遍 → 通过后展示给用户
```

### 5.2 减少用户修改次数

用户看到的是 AI 已经自检过的结果，不是裸输出。目标：每章用户点一次"通过"就行。

## 七、技术选型

### 7.1 技术栈总览

| 层 | 选型 | 理由 |
|----|------|------|
| **PPT 生成引擎** | power-pptx | python-pptx 活跃 fork，自带防溢出/设计令牌/审计/Claude Code Skill |
| **AI 编排** | Claude Code Skill | V1 在对话中运行，问卷引导+逐章生成 |
| **模板描述** | JSON（detail.json） | 借鉴 GordenSun，描述每页槽位和角色 |
| **设计令牌** | power-pptx `DesignTokens` | 配色/字体/间距统一管理，从模板提取后存为配置 |
| **运行环境** | Python 3.12 | 当前已装 `C:\Users\277417\AppData\Local\Programs\Python\Python312\` |
| **V2 界面** | Gradio | 轻量表单式交互，支持文件拖拽上传 |
| **版本控制** | Git + GitHub | 模板和 edits.json 都可 diff |

依赖：`pip install power-pptx`（完全兼容 python-pptx API，原代码无需改动）

### 7.2 三条技术路线对比

AI PPT 生成有三条路线，只有一条产出真正可编辑的原生 PPTX：

| 路线 | 出品 | 可编辑 | 适用 |
|------|------|:--:|------|
| **Native PPTX** | 矢量形状、文本框、图表，PowerPoint 里可逐字改 | ✅ | ← 我们的选择 |
| HTML 网页 | 视觉惊艳但导出 PPTX 格式会乱 | ❌ | 发布会/个人演示 |
| AI 生图 | 每页一张高质量图片，改一个字要重新生成 | ❌ | 封面/社交媒体 |

### 7.3 Native PPTX 核心库选型

| 库 | 定位 | 为什么 |
|----|------|--------|
| **[power-pptx](https://github.com/nickatnight/power-pptx)** ⬅ 选它 | python-pptx 活跃 fork，MIT 协议 | 自带防溢出、设计令牌、Claude Code Skill、JSON 驱动、整份审计 |
| [python-pptx](https://github.com/scanny/python-pptx) | 原版，停在 v1.0.2 | 功能基础，维护停滞，60 行代码画一页 |
| [Office Oxide](https://github.com/yfedoseev/office_oxide) | Rust 核心 | 100× 快但**只能读不能写**，不适合生成 |

### 7.4 power-pptx 对需求的一一匹配

| 我们的需求 | power-pptx 对应能力 |
|-----------|-------------------|
| edits.json 模式（只换文字不改排版） | `from_spec()` JSON 驱动生成 |
| 文字超出文本框检测 | `fit_text()` + `tidy()` 自动防溢出 |
| 设计令牌（配色+字体+间距统一管理） | `DesignTokens` 类 |
| Claude Code Skill 内建 | 自带 skill 文件 |
| 整份 PPT 审计（AI 自检修复环） | `audit(prs)` 扫描问题 |
| 原生图表数据绑定 | chart 更新 API |
| 图表配方（架构图/漏斗/时间线） | 内置 `horizontal_pipeline` `cycle` 等 |

### 7.5 代码量对比

```
python-pptx：60 行代码画一页，所有细节手写，没有防溢出
power-pptx：同一页 15 行，fit_text 防溢出，tidy 自动对齐，audit 扫全稿
```
