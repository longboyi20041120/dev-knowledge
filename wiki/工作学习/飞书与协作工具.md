# 飞书与协作工具

企业协作平台的开发能力学习笔记，以飞书（Lark）为核心，覆盖 API 开发、机器人、多维表格等方向。

## 飞书开放平台概述

飞书提供完整的开发者生态：

| 能力 | 说明 | 典型场景 |
|------|------|----------|
| 服务端 API | RESTful 接口，覆盖消息、日历、文档、通讯录 | 自动发通知、同步组织架构 |
| 事件订阅 | Webhook 推送，实时响应事件 | 审批流自动化、入离职提醒 |
| 机器人 | 应用机器人 + 自定义机器人 | 客服问答、数据查询 |
| 多维表格 | 在线数据库，支持公式和自动化 | 项目管理、数据收集 |
| 飞书应用 | 小程序 + H5 应用 | 定制化工作台 |

## 认证机制

飞书 API 使用 OAuth 2.0 + Token 体系：

- **tenant_access_token**：应用级凭证，有效期 2 小时
- **user_access_token**：用户级凭证，用于访问用户资源
- Token 存储建议：Redis 缓存 + 提前刷新机制

```
获取 token → 缓存 1.5h → 过期前 30min 刷新 → 重试机制
```

参考问题：[飞书 lark-cli 如何存储 tenant_access_token 和 user_access_token](https://juejin.cn/post/7656751882111696923)

## 消息推送

- 支持文本、富文本、卡片、图片等多种消息类型
- 卡片消息（Card）支持交互按钮和数据回传
- 批量发送需注意频率限制（QPS 上限）

## 多维表格

飞书多维表格本质是一个轻量级在线数据库：
- 支持公式计算、关联引用、视图筛选
- 可通过 API 读写数据
- 适合做轻量级 CRM、项目追踪、数据看板

## 产品分析视角

飞书属于典型的 **B2B SaaS + 留存微笑曲线** 产品：
- 初期留存可能下降（用户不习惯新协作方式）
- 使用一个月后留存回升（组织数据积累形成迁移成本）
- 优化重点是"让用户尽快进入积累阶段"——新手引导导入组织架构和历史文档
