# 飞书开发 + 设计思维学习计划

五阶段学习计划，飞书开发与设计思维双线并行推进。

## 总体框架

```
飞书开发线：环境搭建 → 消息 API → 数据管理 → 流程自动化 → 整合应用
设计思维线：同理心   → 定义问题 → 构思方案 → 原型测试 → 迭代优化
          ╲         ╱         ╲         ╱         ╲
           阶段一             阶段二             阶段三 ...
```

## 阶段一：环境与理解

| 飞书开发 | 设计思维 |
|----------|----------|
| 注册飞书开发者账号 | 同理心：理解用户协作痛点 |
| 创建应用、获取 App ID/Secret | 观察团队目前的协作流程 |
| 跑通 Hello World API 调用 | 记录 3 个现有流程的改进点 |

**产出**：一个能发消息的飞书机器人 + 一份用户痛点清单

## 阶段二：消息与定义

| 飞书开发 | 设计思维 |
|----------|----------|
| 文本消息、卡片消息 | 定义问题：提炼核心需求 |
| 事件订阅（Webhook） | 用户故事地图 |
| 消息批量发送与频率控制 | 优先级排序（影响 × 可行性） |

**产出**：定时推送消息的机器人 + 3 个优先级排序的需求

## 阶段三：数据与构思

| 飞书开发 | 设计思维 |
|----------|----------|
| 多维表格 API 读写 | 构思方案：头脑风暴 |
| 数据模型设计（字段、关联） | 竞品分析（钉钉、企微等） |
| 数据同步与备份 | 技术可行性评估 |

**产出**：一个可编程的多维表格应用 + 方案对比文档

## 阶段四：流程与原型

| 飞书开发 | 设计思维 |
|----------|----------|
| 审批流对接 | 原型测试：低保真原型 |
| 自动化规则（if-this-then-that） | 用户测试与反馈收集 |
| 权限管理与安全 | 迭代修改 |

**产出**：自动化审批流程 + 用户测试报告

## 阶段五：整合与迭代

| 飞书开发 | 设计思维 |
|----------|----------|
| 多应用整合（消息 + 表格 + 审批） | 迭代优化：数据驱动决策 |
| 性能优化与监控 | A/B 测试 |
| 上线发布与运维 | 复盘与文档沉淀 |

**产出**：一个完整的飞书企业应用 + 项目复盘文档
