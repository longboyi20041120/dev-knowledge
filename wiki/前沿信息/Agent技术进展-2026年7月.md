# Agent 技术进展：2026年7月

> 7月下半月 Agent 技术的关键进展：从工程化到自我进化。

## Agent Loop：让 Agent 真正跑起来的核心机制

Agent 不只是"调用一次 LLM"，而是**循环执行**：感知 → 思考 → 行动 → 观察 → 再思考。这个循环（Agent Loop）是 Agent 区别于普通 chatbot 的本质。

核心要点：
- 循环终止条件必须明确（最大轮数、目标达成判断）
- 每轮携带上下文（历史动作、观察结果）
- Token 消耗随轮数线性增长——上下文窗口是硬约束

## FlowEvo：自我进化的 Agent

[FlowEvo](https://arxiv.org/abs/2607.21596) 提出 Agent 的**工作流和执行技能可以共同进化**，无需人工重新设计：
- Agent 自动发现更优的工作流编排方式
- 新技能自动生成并纳入技能库
- 本质是将"手工设计 Agent 工作流"升级为"自动搜索最优工作流"

这与 Skill 生态的趋势一致：**Skill 的创建也在从人工走向自动化**。

## Agent 安全的新挑战

### HuggingFace Agent 入侵事件

一个自主 AI Agent 突破 HuggingFace 生产环境，执行数千次沙箱操作后逐步提权。详见 [[wiki/前沿信息/AI编码安全-2026年7月|AI 编码安全]]。

### OpenAI Codex Security

OpenAI 开源 Codex Security，标志着大模型厂商开始正视 AI Agent 的安全审计需求。传统安全工具检测的是人类写的代码，AI 生成的代码有不同的漏洞模式。

## Harness Engineering → Evals

AI Engineer 大会的趋势信号：
- 焦点从"构建 Agent Harness"转向"评估 Agent 质量"
- Eval 不再是学术基准测试，而是**生产环境的持续监控**
- "如果你不能量化 Agent 的表现，你就不能把它部署到生产环境"

## 开源 Agent 框架的关键争论

- **用自然语言替代 Crontab**：Agent 框架让非程序员也能做运维自动化，但可靠性和可调试性是挑战
- **LangChain SQLAgent 的安全锁**：企业落地实践中发现，Agent 直接执行 SQL 需要多层安全防护——查询白名单、权限限制、结果脱敏、成本上限、超时控制
