## 4.到底什么是微调
![[到底什么是微调.jpg]]
### 微调方法
- 全量微调：相当于把整个模型从头到尾重新“装修”一遍。所有参数都参与训练，效果上限最高，但代价是计算资源消耗大、训练时间长，且容易因数据不足导致过拟合或遗忘原有知识。适合数据充足、追求极致性能的场景

- 冻结微调：只“翻新”模型的顶层部分，底层通用能力保持不变。通过冻结大部分参数，仅训练最后几层或分类头，大幅降低计算成本，同时保留预训练模型的通用理解力。适合任务与预训练目标相似、数据量中等的情况。

- Lora微调：在模型内部“加装一个小型适配器”，只训练这个适配器里的少量参数，原模型完全不动。训练快、显存占用低、可保存多个不同任务的适配器，非常适合个人实验、小样本任务或需要快速切换风格的场景

## 模型的选择
|维度|选项|视频推荐|理由|
|---|---|---|---|
|**模型家族**|qwen3、llama3、deepseek 等|**qwen3**|性能好、教程多、品类齐全|
|**模型阶段**|预训练模型、chat 微调、instruct 微调|**instruct 微调**|对新手最友好，难度与效果平衡|
|**模型大小**|0.6B、1.7B、4B、8B、14B 等|无固定推荐，**够用前提下越小越好**|提升速度、节省资源|
|**思考模式**|推理模型 / 非推理模型|能用非思考就不用思考模式|节省资源、提升速度|
## 微调数据准备
### 数据集准备的3个关键
1. 数据质量比数据量重要
	- 无论从什么形式获取数据，都要进行质量评估 
2. 数据量不要太多也不要太少
	- 太少：欠拟合
	- 太多：遗忘预训练知识
3. 注意数据的多样性
	- 覆盖可能出现的各种问题、问法
	- 输入数据和输出数据应分开构造
	- 提示词要尽量差异化
### 核心原则
> 上线后用户会怎么，微调数据就怎么准备
> 训练数据的风格要尽量贴近实际使用场景，避免用“官话”生成数据去训练“人话”场景
### 准备数据集的三个方法
- 人工准备
- 开源数据
	- 魔搭
	- 天池
	- 百度飞桨
- 模型生成（蒸馏）+人工检查

### 数据生成的方式
1. **公开数据集**：如 `modelscope download --dataset alleyf/HUST-Student-Handbook`
2. **大模型 API 蒸馏**：
    - 构造多样化输入提示词
    - 调用 GLM-4.6 / 其他大模型生成"劣质报告"
    - 再构造优化提示词，让模型生成"优质报告"
    - 将输入输出组合成训练数据
3. **Easy DataSet 工具**：上传文献，自动生成问题和数据集
### 数据生成代码示例（劣质报告 → 优质报告）

```python
import random
from openai import OpenAI

# 构造输入端提示词
def generate_input_prompt():
    roles = ['初级产品经理', '高级项目经理', '技术负责人', '数据产品经理']
    tasks = ['工单流程开发', 'BI看板开发', '文本分类模型建设', ...]
    report_types = ['周报', '月报', '建设进展', '工作总结']
    word_counts = [80, 120, 150, 200]
    problem_categories = ['逻辑混乱', '口语化严重', '流水账', '缺乏数据支撑', '价值点缺失']

    role = random.choice(roles)
    task = random.choice(tasks)
    report_type = random.choice(report_types)
    word_count = random.choice(word_counts)
    selected_problems = random.sample(problem_categories, 3)

    prompt = f"""
    # 角色和要求
    作为{role}，请撰写一份关于{task}的{report_type}。这份报告应该是一个典型的"反面教材"。
    ## 需要突出的问题特征（重点体现：{', '.join(selected_problems)}）：
    ...
    """
    return prompt, {...}

# 调用大模型生成劣质报告
client = OpenAI(api_key=api_key, base_url=base_url)
def generate_input_sample():
    prompt, _ = generate_input_prompt()
    response = client.chat.completions.create(
        model=model_name,
        messages=[{"role": "user", "content": prompt}]
    )
    return response.choices[0].message.content

# 构造输出端提示词：将劣质报告优化为优质报告
def generate_output_prompt(original_text):
    return f"""
    你现在是一位经验丰富的办公室秘书，擅长将普通文本优化为专业、结构清晰、符合领导预期的优质报告。
    请根据提供的普通文本进行优化...
    ## 待优化的文本
    {original_text}
    """

# 批量生成微调数据
finetune_results = []
for original_text in input_distill:
    prompt = generate_output_prompt(original_text)
    response = client.chat.completions.create(
        model="glm-4.5-x",  # 需要支持思维链输出
        messages=[{"role": "user", "content": prompt}],
        top_p=0.8,
        temperature=0.9,
        extra_body={"thinking": {"type": "enabled"}}
    )
    message = response.choices[0].message
    finetune_results.append({
        "instruction": "优化报告",
        "input": original_text,
        "output": "<think>" + message.reasoning_content + "</think>\n" + message.content
    })
```
### 从文档生成数据集的注意事项
**主要局限**：

1. **上下文有限**：长文档切分后容易丢失上下文
2. **问题质量差**：直接生成的问题可能过于简单或偏离重点

**改进策略**：

1. **Markdown 分块**：按文档结构切分
    - 按 `# 一级标题`、`## 二级标题` 切分
    - 再按换行符、句号进一步切分
2. **多角度生成问题**：针对同一段内容，从不同目标体裁/受众角度生成不同问题
3. **人工检查**：模型生成的数据必须经过人工校验
4. **迭代闭环**：蒸馏数据 → 训练模型 → 上线应用 → 收集真实数据 → 再训练

### 关键参数详解

#### template（对话模板）

对话模板的作用是将人类的自然语言格式化为模型能够理解的指令格式。不同的模型家族（Qwen、Llama、DeepSeek 等）通常有各自的模板。

视频中以 Qwen3 为例，使用 `template: default` 即可，LLaMA-Factory 会自动匹配 Qwen3 的对话模板。

选择原则：

- 基座模型（Base）和 指令微调模型（Instruct/Chat）的模板可能不同
- 使用与模型配套的模板，否则训练效果会大打折扣
- 不确定时，可在 LLaMA-Factory 的 `template` 配置中查看支持的模板列表

#### lora_rank

|r 值|效果|代价|推荐|
|---|---|---|---|
|8|ΔW 表达简单|参数量小|通用首选|
|16|ΔW 表达丰富，学得深|参数量大，可能过拟合|复杂任务|

#### learning_rate（学习率）

控制参数更新幅度：

```
新参数 = 旧参数 - 学习率 × 梯度
```

- 太大：可能错过最优解，训练不收敛
- 太小：参数几乎不更新，白学
- 推荐范围：**10⁻⁵ ~ 10⁻⁴**

#### max_samples & num_train_epochs

```
总训练数据量 = max_samples × num_train_epochs
```

- `max_samples`：从数据集抽取的样本数
    - 技巧：**先用小数据量快速测试，确保参数无误**
- `num_train_epochs`：所有数据训练几轮

#### eval_strategy / eval_steps / save_steps

```yaml
eval_strategy: steps    # 按步数评估
eval_steps: 50          # 每 50 次参数更新评估一次
save_steps: 50          # 每 50 次保存一次模型
```

好处：每个保存的模型都有评估指标，方便挑选最佳模型。

#### cutoff_len（数据截断长度）

- **问题**：Attention 机制显存需求是平方级增长
- **风险**：某一条数据过长可能撑爆显存
- **原则**：90% 的数据在截断长度以内
- **注意**：不能太短，否则可能截掉关键答案部分

#### per_device_train_batch_size & gradient_accumulation_steps

这两个参数的组合可以实现"用时间换空间"：

|参数|组合 1|组合 2|
|---|---|---|
|per_device_train_batch_size|1|4|
|gradient_accumulation_steps|4|1|

- **组合 1**：显存低、耗时长（小 batch + 多步累积）
- **组合 2**：显存高、耗时短（大 batch + 少步累积）

**原理**：4 个样本分 4 次前向传播，累积梯度后更新一次，与一次处理 4 个样本的**效果相同**。

#### QLoRA 量化

```yaml
quantization_bit: 8   # INT8 量化，显存降至 1/2
quantization_bit: 4   # INT4 量化，显存降至 1/4
```

代价：精度下降、计算时间变长。显存不够时使用。

### 训练诊断流程

视频 90-92 分钟给出了一个清晰的训练问题排查流程：

```
训练集 loss 是否下降？
    ├── 否 → 数据本身有问题，检查数据质量
    └── 是 → loss 是否平稳/波动？
              ├── 波动大 → 调整学习率、batch size 等
              └── 平稳 → 看测试集 loss
                            ├── 测试集 loss 也下降 → 训练正常
                            └── 测试集 loss 上升 → 过拟合，减少 epoch 或增加数据多样性
```

**诊断要点**：

- 训练集 loss 不下降：通常是数据格式错误或数据质量太差
- 训练集 loss 波动大：学习率可能过大
- 训练集 loss 下降但测试集 loss 上升：过拟合，需要减少训练轮次或增加数据量/多样性
